# Brief — PR-03.5.2.1 — FTS Weighted Ranking (name > description)

> **Status**: `APPROVED`
> **Scope**: `MVP`
> **Archivo**: `docs/plan/pr-briefs/PR-03.5.2.1-fts-weighted-ranking.md`
> **Issue**: [#129](https://github.com/ferbbo/closy-bot/issues/129) (1 issue con todos los REQs)
> **Parallel Mode**: `true` (worktree)
> **Base branch**: `onboarding`
> **Regla**: Max 2 páginas. Spec-locked. Sin scope extra.

## Objetivo

Mejorar la relevancia del Full-Text Search del catálogo (FTS) para que coincidencias en `name` pesen más que coincidencias en `description`, evitando falsos positivos (p. ej. match por un adjetivo en la descripción de productos no relacionados).

## Scope fence

### ✅ Included

- Agregar tsvector ponderado `search_text_weighted` (A/B/C/D) para ranking.
- Actualizar query FTS para rankear usando `search_text_weighted`.
- Tests e2e que validen orden de resultados (ranking) en casos reales.

### ❌ Excluded

- Cambiar config FTS (`simple` → `spanish`) o stemming.
- Sinónimos, `pg_trgm`, embeddings o mejoras de fuzzy matching.
- Cambios de UX/conversación (eso es PR-04.1).

## Comportamiento

- Happy path:
  - Query FTS encuentra matches y ordena por `ts_rank(search_text_weighted, tsquery)`.
  - Productos con el término en `name` aparecen antes que productos donde el término aparece solo en `description`.

- Edge cases:
  - Catálogo con `brand/tags/description` nulos: se maneja con `COALESCE`.
  - Query vacía: retorna `[]` (comportamiento existente).
  - Compatibilidad: se mantiene fallback existente (normalización, trigram, ILIKE).
