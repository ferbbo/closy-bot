## 1. Objetivo

Habilitar la **conversación end-to-end** (recibir → entender → responder por WhatsApp) y cumplir con los requisitos funcionales **RF-01 a RF-11** del MVP Core V1.

### Problema actual

| Componente | Estado |
|------------|--------|
| Webhook inbound + dedupe | ✅ Implementado |
| CustomerService / ConversationService | ✅ Implementado |
| CatalogService (búsqueda) | ✅ Implementado |
| **WhatsApp Outbound Sender** | ❌ No existe |
| **Orchestrator** | ❌ Placeholder vacío |
| **Conexión inbound → identity → respuesta** | ❌ No existe |

**Resultado:** El bot recibe mensajes pero nunca responde. No puede "conversar" ni mostrar productos.

---

## 2. Scope fence

### ✅ Included

**2.1 WhatsApp Outbound Sender**
- `WhatsAppOutboundService` para enviar mensajes via Meta Cloud API
- Tipos de mensaje: texto simple (V1)
- Config via env: `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_API_VERSION`
- Manejo de errores y logging
- Rate limiting básico (opcional pero recomendado)

**2.2 Orchestrator básico**
- `ConversationOrchestrator` que conecta el pipeline completo
- `MerchantResolverService` para resolver merchant por número receptor
- `IntentRouterService` simple por keywords/regex:
  - `SEARCH_PRODUCT`: busco, quiero, tienes, producto, necesito
  - `GREETING`: hola, buenos días, buenas tardes
  - `HELP`: ayuda, cómo funciona, menú
  - `UNKNOWN`: fallback

**2.3 Flujo de búsqueda catálogo**
- Detectar intent SEARCH_PRODUCT → extraer query → buscar en CatalogService
- Formatear resultados: nombre, precio, stock (máx 5 productos)
- Responder via OutboundService

**2.4 Conexión del pipeline**
- Modificar `WhatsAppController.handleInbound()` para:
  1. Resolver merchant por número receptor
  2. Resolver customer/conversation
  3. Llamar Orchestrator
  4. Enviar respuesta via OutboundService

### ❌ Excluded

- LLM/NLP (usar keywords simples)
- Carrito (agregar/remover items)
- Checkout
- Imágenes/adjuntos en respuestas
- Botones interactivos de WhatsApp
- Templates de WhatsApp
- Multi-tenant avanzado (un merchant para MVP)

## 4. Contratos / Interfaces

### 4.1 WhatsApp Outbound

```typescript
interface WhatsAppOutboundService {
  sendTextMessage(to: string, text: string): Promise<SendMessageResult>;
}

interface SendMessageResult {
  success: boolean;
  messageId?: string;
  error?: string;
}
```

### 4.2 Intent Router

```typescript
type IntentType = 'SEARCH_PRODUCT' | 'GREETING' | 'HELP' | 'UNKNOWN';

interface IntentResult {
  intent: IntentType;
  confidence: number;
  entities?: {
    query?: string;  // extracted search query
  };
}

interface IntentRouterService {
  classify(text: string): IntentResult;
}
```

### 4.3 Orchestrator

```typescript
interface OrchestratorInput {
  messageId: string;
  from: string;           // sender phone
  receiverPhoneId: string; // WhatsApp phone number ID
  text: string;
  timestamp: Date;
}

interface OrchestratorResult {
  response: string;
  shouldSend: boolean;
  conversationId: string;
  intent: IntentType;
}

interface ConversationOrchestrator {
  process(input: OrchestratorInput): Promise<OrchestratorResult>;
}
```

## 9. Acceptance criteria (verificables)

```gherkin
Feature: Conversación básica por WhatsApp

  Scenario: Usuario saluda
    Given un mensaje inbound con texto "hola"
    When el orchestrator procesa el mensaje
    Then el bot responde con un saludo y opciones

  Scenario: Usuario busca producto
    Given un catálogo con productos "zapatillas running"
    And un mensaje inbound con texto "busco zapatillas"
    When el orchestrator procesa el mensaje
    Then el bot responde con lista de zapatillas (nombre, precio, stock)

  Scenario: Mensaje duplicado
    Given un mensaje ya procesado con message_id "xyz123"
    When llega otro mensaje con el mismo message_id
    Then no se envía respuesta duplicada
    And el webhook retorna 200 con duplicate=true
```
