# PR Brief — PR-03.7 — Catalog Management API (Import masivo + CRUD)

> Archivo: `docs/plan/pr-briefs/PR-03.7-catalog-management-api.md`
>
> Regla: 1 página. Machine-actionable. Sin scope extra.

## Objetivo

Exponer endpoints HTTP mínimos para que un merchant pueda (1) cargar/actualizar su catálogo por CSV y (2) administrar productos/variantes con CRUD básico, manteniendo multi-tenancy y guardrails.

## Scope fence

### ✅ Included

- Bulk import por CSV usando `ImportService.importFromCSV()`
- CRUD básico de productos + variantes (mínimo viable)
- Multi-tenancy: todas las operaciones scoped a `merchantId`
- Auth simple por `merchant.apiKey`
- Validación DTOs (whitelist/transform) y límites básicos de payload
- Tests unit + e2e básicos

### ❌ Excluded

- UI/Admin dashboard
- Integraciones POS/ERP/Shopify/Woo (webhooks/sync)
- Editor avanzado de catálogo, versionado, auditoría
- Manejo de CSV con comillas/escapes complejos (MVP: parser simple existente)

## Paths a tocar (concretos)

- apps/api/src/services/import.service.ts (reuso; ajustes solo si es imprescindible)
- apps/api/src/services/catalog.service.ts (reuso)
- apps/api/src/persistence/repositories/product.repository.ts
- apps/api/src/common/ (auth guard / middleware)
- apps/api/src/ (nuevo módulo/controller para catalog management)
- apps/api/test/ (e2e)

## Contratos / Interfaces

- Endpoints (MVP):
  - `POST /api/catalog/import` (Content-Type: `text/csv`) → `{ success, created, updated, errors[] }`
  - `GET /api/products` (query: `q`, `category`, `limit`, `cursor?`) → lista scoped a merchant
  - `GET /api/products/:id` → producto + variantes (scoped)
  - `POST /api/products` → crear producto + (opcional) variantes
  - `PATCH /api/products/:id` → actualizar campos básicos
  - `DELETE /api/products/:id` → soft delete (`isActive=false`)

- Auth:
  - `Authorization: Bearer <merchantApiKey>` (preferido) o `x-api-key: <merchantApiKey>`
  - Resolver `merchant` por `apiKey` (no por `receiver_phone_id`)

- Persistencia (Prisma/models):
  - No agregar tablas nuevas (reusar `Product`, `ProductVariant`, `Category`)

- Idempotencia:
  - Bulk import: upsert por `sku` (ya implementado)

## Comportamiento

- Happy path:
  - Import CSV válido → crea/actualiza productos y retorna stats
  - CRUD producto → opera solo dentro del merchant autenticado

- Edge cases:
  - Auth inválida → 401
  - Producto de otro merchant → 404 (no filtrar existencia cross-tenant)
  - CSV vacío/header inválido → 400
  - Import parcial: retorna `errors[]` por fila, no revienta toda la carga

## Acceptance criteria (verificables)

- [ ] Endpoint `POST /api/catalog/import` importa el template y retorna stats consistentes
- [ ] CRUD de productos está scoped a merchant (no cross-tenant)
- [ ] Import por SKU es idempotente (2 cargas no duplican)
- [ ] Tests unit y e2e cubren happy path + cross-tenant

## Comandos para validar

- `pnpm lint`
- `pnpm test`
- (si aplica) `pnpm test:e2e`

## Riesgos y mitigaciones

- CSV parser simple (sin quotes/commas) → documentar limitación en el endpoint y template
- Riesgo de payload grande → limitar tamaño y procesar por batches (ya existe `BATCH_SIZE`)

## Notas

- Guardrails: el bot NO inventa precio/stock/políticas/ETA.
- PII: evitar logs con teléfonos/direcciones; mask en logs.
