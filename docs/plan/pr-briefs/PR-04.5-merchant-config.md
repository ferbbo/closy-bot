## Objetivo

Persistir configuración operativa del merchant (métodos de pago aceptados, política de envío, política de devolución) con presets por industria para simplificar el setup y preparar checkout (PR-05).

## Scope fence

### ✅ Included

- Modelo Prisma `MerchantConfig` (1:1 con Merchant) con campos JSON validados
- Campos: `paymentMethods`, `shippingConfig`, `returnPolicy`, `currency`, `orderCodePrefix`, `autoConfirmCod`
- Presets de industria (ropa, belleza, minimarket) — patrón similar a Playbooks (PR-11)
- Service: `getOrCreateConfig()`, `updateConfig()`, `getConfigWithDefaults()`
- Endpoints API (Session auth): `GET /merchants/me/config`, `PATCH /merchants/me/config`
- Seed que crea `MerchantConfig` al crear merchant con presets de industria
- Tests unit + e2e (multi-tenancy, presets, PATCH partial update)
- Actualización de `BACKEND-EXECUTION-GUIDE.md` con cURL examples
- Consumer-first design: endpoints directamente consumibles desde UI/cURL

### ❌ Excluded

- Payment gateway integration (ej: Stripe, MercadoPago)
- Shipping provider integration (ej: Coordinadora, Servientrega)
- Cálculo dinámico de costos de envío
- UI/frontend (PR-FE-05)
- Validación de información bancaria
- Multi-moneda real (solo almacenar código de moneda)

## Contratos / Interfaces

### Persistencia (Prisma)

```prisma
model MerchantConfig {
  id              String    @id @default(cuid())
  merchantId      String    @unique @map("merchant_id")
  paymentMethods  Json      @map("payment_methods")   // PaymentMethodConfig[]
  shippingConfig  Json      @map("shipping_config")   // ShippingConfig
  returnPolicy    String?   @map("return_policy") @db.Text
  currency        String    @default("COP")
  orderCodePrefix String    @default("ORD") @map("order_code_prefix")
  autoConfirmCod  Boolean   @default(true) @map("auto_confirm_cod")
  createdAt       DateTime  @default(now()) @map("created_at")
  updatedAt       DateTime  @updatedAt @map("updated_at")

  merchant Merchant @relation(fields: [merchantId], references: [id], onDelete: Cascade)

  @@map("merchant_configs")
}
```

### Endpoints

#### `GET /merchants/me/config`
- **Auth**: Session Cookie (SessionAuthGuard)
- **Response**: `MerchantConfigResponseDto`
- **Consumer Experience**: 
  - UI: dashboard fetches config al cargar página de settings
  - cURL: testeable con cookie de sesión

#### `PATCH /merchants/me/config`
- **Auth**: Session Cookie (SessionAuthGuard)
- **Request**: `UpdateMerchantConfigDto` (partial)
- **Response**: `MerchantConfigResponseDto`
- **Consumer Experience**:
  - UI: submit form con solo campos modificados
  - cURL: testeable con JSON partial en body

### DTOs / payloads

#### PaymentMethodConfig (TypeScript type)
```typescript
{
  type: 'cod' | 'transfer' | 'payment_link',
  label: string,              // Display name (ej: "Contraentrega", "Transferencia Bancolombia")

    accountNumber: string,
    accountType: 'ahorros' | 'corriente',
```

```typescript

}
```

## Comportamiento

### Happy path

1. Merchant se registra con industria "ropa"
2. Seed crea `Merchant` + `MerchantConfig` con preset de ropa
3. `GET /merchants/me/config` retorna config con preset aplicado
4. Merchant edita `returnPolicy` via `PATCH /merchants/me/config`
5. Solo `returnPolicy` se actualiza, otros campos quedan igual

### Edge cases

- **Merchant sin MerchantConfig**: `getOrCreateConfig()` crea uno con preset de industria (fallback "ropa" si industry null)
- **PATCH con campos inválidos**: validación de DTOs retorna 400 con detalles
- **Multi-tenancy**: merchant solo puede acceder a su propia config (enforced por SessionAuthGuard + session.merchantId)
- **Campos null en PATCH**: mantener valor existente (no sobrescribir con null)

## Consumer Experience (API Design)

### Diseño consumer-first

- **cURL testeable**: endpoints funcionan con cookie simple (no transformaciones)
- **Auth consistente**: Session Cookie (igual que `/auth/me`, coherente con dashboard endpoints)
- **Errores accionables**: validación de DTOs retorna 400 con mensajes claros por campo
- **Response structure**: consistente con otros endpoints de merchant-settings

### Ejemplo cURL completo

```bash
# 1. Login (en navegador) → obtener session_id
open "http://localhost:3000/auth/login/google"

# 2. Get config actual
curl -X GET http://localhost:3000/merchants/me/config \
  -H "Cookie: session_id=<tu-session-id>" \
  -H "Content-Type: application/json"

# 3. Actualizar solo returnPolicy
curl -X PATCH http://localhost:3000/merchants/me/config \
  -H "Cookie: session_id=<tu-session-id>" \
  -H "Content-Type: application/json" \
  -d '{
    "returnPolicy": "Cambios hasta 15 días con producto sin usar."
  }'

# 4. Actualizar paymentMethods
curl -X PATCH http://localhost:3000/merchants/me/config \
  -H "Cookie: session_id=<tu-session-id>" \
  -H "Content-Type: application/json" \
  -d '{
    "paymentMethods": [
      { "type": "cod", "label": "Contraentrega" },
      { 
        "type": "transfer", 
        "label": "Transferencia Bancolombia",
        "bankInfo": {
          "bankName": "Bancolombia",
          "accountNumber": "1234567890",
          "accountType": "ahorros",
          "accountHolder": "Mi Tienda SAS"
        }
      }
    ]
  }'
```
