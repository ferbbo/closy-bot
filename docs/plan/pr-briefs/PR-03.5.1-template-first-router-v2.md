# Brief — PR-03.5.1 — Template-First Router + IntentRouter V2

> **Status**: `APPROVED`

## Objetivo

Invertir la lógica del orchestrator para que flows determinísticos (templates) ejecuten SIEMPRE primero, e introducir IntentRouter V2 con scoring real, normalización, y confidence calculada. Minimizar costos LLM al 15-20% del tráfico (solo intents UNKNOWN) eliminando el toggle binario `LLM_ENABLED` por flags granulares.

## Scope fence

### ✅ Included

- **IntentRouter V2**: scoring por keyword, normalización (tildes, espacios), confidence calculada (HIGH/MED/LOW), resolución de colisiones, context-aware routing (lastIntent)
- **Nuevos tipos**: `IntentKey`, `IntentDecision`, `RouteDecision`
- **RouteDecisionService**: classifyAndRoute() con decisión de TEMPLATE_ROUTE vs LLM_FALLBACK_ROUTE
- **Orchestrator rewrite**: eliminar toggle binario `LLM_ENABLED`, nuevo flujo template-first
- **Feature flags granulares**: `LLM_INTENT_ASSIST`, `LLM_FALLBACK_ENABLED`, `LLM_SUMMARY_ENABLED` (reemplazan `LLM_ENABLED` monolítico)
- **Nuevos intents**: `AMBIGUOUS` (colisión de múltiples intents)
- **Logging structured**: intent, confidence, signals, route, latencyMs por request
- Tests unit + e2e (reducción costos, template-first priority)

### ❌ Excluded

- TemplatePack en DB (Bloque 7 PR-20)
- Handlebars render (Bloque 7 PR-22)
- ContextPack formal (Bloque 7 PR-21)
- Session slots complejos (beyond lastIntent)
- Telemetry dashboard/OpenTelemetry (Bloque 7 PR-25)
- Cambios en flows existentes (excepto integración con RouteDecisionService)
- FAQ flow (PR-GAP-2)
- FTS (PR-03.5.2)
- MerchantConfig (PR-04.5)

## Comportamiento

### Happy path (template-first)

1. Cliente envía "busco camisetas"
2. `IntentRouter.classify()` → normaliza texto → `busco camisetas`
3. Score keywords: `SEARCH_PRODUCT` = 3 (keyword "busco"), otros = 0
4. Confidence: score 3 > threshold_low (2) → `MED`
5. `IntentDecision { intent: SEARCH_PRODUCT, confidence: MED, signals: ['busco'] }`
6. `RouteDecisionService.classifyAndRoute()` → confidence MED → `TEMPLATE_ROUTE`
7. `Orchestrator` → ejecuta `SearchCatalogFlow` (template determinístico)
8. **LLM cost: $0** (no LLM call)

### Happy path (LLM assist para UNKNOWN)

1. Cliente envía "eso me gusta"
2. `IntentRouter.classify()` → score todos intents < threshold_low → `UNKNOWN`
3. `RouteDecisionService`: UNKNOWN + `LLM_INTENT_ASSIST=true` → call LLM con prompt corto
4. LLM responde: "intent: ADD_TO_CART" (basado en context.lastIntent = SEARCH_PRODUCT)
5. Retry classify con hint → match → `ADD_TO_CART`
6. `RouteDecision { route: TEMPLATE, intent: ADD_TO_CART }`
7. Ejecuta `AddToCartFlow` (template determinístico)
8. **LLM cost: 1 classify call (~100 tokens)** vs antes 1 generación (~500 tokens)

### Edge cases

- **Colisión (AMBIGUOUS)**: "quiero" match keywords de `ADD_TO_CART` (3 pts) y `SEARCH_PRODUCT` (1 pt). Score diff > 2 → selecciona `ADD_TO_CART` (mayor score). No es AMBIGUOUS.
- **Colisión real**: "agregar mostrar" → `ADD_TO_CART` = 2, `SEARCH_PRODUCT` = 2. Diff = 0 < 2 → `AMBIGUOUS` → retry con LLM si `LLM_INTENT_ASSIST=true`
- **Normalización tildes**: "búsco" → "busco" → match keyword
- **Context-aware**: lastIntent=SEARCH_PRODUCT + "quiero" → boost ADD_TO_CART score (+2 bonus)
- **LLM fallback falla**: timeout/error → log warning, return `GENERIC_ROUTE` con mensaje hardcoded "No entendí, escribe 'ayuda'"
- **Todos flags false**: UNKNOWN → `GENERIC_ROUTE` → mensaje hardcoded sin LLM

## Constraints

- Guardrails: el bot NO inventa precio/stock/políticas/ETA (ya garantizado por flows determinísticos).
- PII: minimizar logs (no loggear texto completo, solo metadata: intent, signals, latency).
- LLM prompt corto para intent assist: máximo 100 tokens para minimize cost.

## Riesgos y mitigaciones

| Riesgo | Mitigación |
|--------|-----------|
| Normalización de tildes rompe algunos keywords | Tests exhaustivos con todos los acentos españoles comunes |
| Context-aware scoring introduce bugs (falsos positivos) | Bonus de contexto conservador (+2 pts), no multiplicativo |
| LLM assist agrega latencia | Timeout corto (2s), fallback a GENERIC si falla |
| Backward compat `LLM_ENABLED` confunde usuarios | Documentar deprecation suave, mantener por 2 releases |
| Logs verbosos → mucho volumen | Structured logs con nivel DEBUG para details, INFO para metrics |

## Tech notes

- **Normalización tildes**: usar librería `remove-accents` (npm) o regex `normalize('NFD').replace(/[\u0300-\u036f]/g, '')`
- **Scoring**: cada keyword tiene peso (1-5). Keywords compuestas (ej: "quiero comprar") tienen mayor peso.
- **Context bonus**: si lastIntent=SEARCH_PRODUCT → intents transaccionales (ADD_TO_CART, VIEW_CART) reciben +2 pts
- **AMBIGUOUS threshold**: si top 2 intents tienen diff score < 2 → AMBIGUOUS
- **LLM intent assist prompt**: corto, con ejemplos few-shot, sin contexto histórico (solo lastIntent)
- **RouteDecisionService**: inyectable, testeable, preparado para mejora en Bloque 7 (template en DB)
- **Modelo de costos**:
  - Antes: 100 mensajes = 100 LLM calls (~500 tokens/call) = 50k tokens
  - Después: 100 mensajes = 15-20 LLM calls (UNKNOWN) = ~8-10k tokens
  - Reducción: ~80-85% costos LLM
