> **Status**: `DRAFT`

## Objetivo

Reescribir los flows de gestión de carrito (`ViewCartFlow`, `RemoveFromCartFlow`, `UpdateCartItemFlow`) para usar `ExpectingService` (PR-04.0) con un flujo multi-paso guiado por números: listar → confirmar acción → ejecutar/pedir cantidad. Agrega `MANAGE_CART` como intent unificado y maneja comandos directos (`"eliminar 2"`, `"modificar 1"`) mediante regex.

> **Dependencia crítica:** PR-04.0 ✅ MERGED (ExpectingService + tipos + PlaybookMessages ya existen).
> **Dependencia soft:** PR-04.1 🔵 PENDIENTE — define el patrón de expecting pre-check en el orchestrator para `search_selection`. PR-04.2 necesita el mismo pre-check para `cart_management`. Si se trabaja en paralelo, este PR también lo implementa (riesgo de conflicto en `conversation.orchestrator.ts` al mergear).

## Scope fence

### ✅ Included

- Nuevo `IntentKey` = `'MANAGE_CART'` en `intent.types.ts`
- `keyword-configs.ts`: keywords para `MANAGE_CART` + regex patterns para `eliminar N`, `modificar N`, `quitar N`, `sacar N`
- `ViewCartFlow.execute()` mejorado: lista numerada con instrucciones + `setExpecting(cart_management/select_action, { cartItems })`
- Expecting pre-check en `ConversationOrchestrator.process()`: si `expecting.flow === 'cart_management'` → dispatch a cart management handler (previo a routing de intent)
- Esperando `select_action`: parseo de "eliminiar N"/"modificar N" → muestra menú de confirmación + `setExpecting(confirm_action, { cartItems, pendingAction, selectedItemIndex })`
- Esperando `confirm_action` + opción 1 → elimina ítem + muestra carrito actualizado + `clearExpecting()`
- Esperando `confirm_action` + opción 2 → pregunta nueva cantidad + `setExpecting(select_quantity, { selectedProduct, maxStock })`
- Esperando `confirm_action` + opción 3 → cancela + `clearExpecting()`
- Esperando `select_quantity`: parsea número → valida vs stock → actualiza + muestra carrito + `clearExpecting()`
- Fallbacks para todos los pasos: número fuera de rango, input no numérico, cantidad > stock, carrito vacío
- Hint al final de cada acción: `"Para seguir modificando: 'modificar carrito'"`
- Uso de helpers existentes: `formatNumberedList()`, `parseNumericSelection()` (PR-04.0)
- Uso de PlaybookMessages existentes: `cartListWithActions`, `cartActionConfirmPrompt`, `cartActionCancelled`, `cartManagementHint`, `cartModifyAskQuantity`, `cartModifySuccess`, `cartRemoveSuccess`, `cartItemNotFound`, `cartEmpty`
- Tests e2e para flujo eliminar y flujo modificar (completos, multi-paso)
- Tests unitarios para regex extraction y parsing

### ❌ Excluded

- Cambio de variante (usuario debe eliminar y re-agregar)
- Bulk operations ("eliminar todo")
- Botones interactivos WhatsApp
- Paginación de carrito >7 ítems (V1: listar todos)
- `"eliminar"` sin número → fallback a listar carrito (sin multi-step por input ambiguo)
- Retrocompatibilidad text-name match (flujo antiguo se reemplaza completamente)

| `cartAction` | `{ action: 'remove' \| 'modify'; index: number } \| undefined` | Extraído del texto cuando hay regex match de "eliminar/modificar N" |

### Flujo `cart_management` — estados de expecting

| `type` | Input esperado | Transición |
|--------|----------------|------------|
| `select_action` | `"eliminar N"`, `"modificar N"`, número N | → `confirm_action` + `pendingAction` + `selectedItemIndex` |
| `confirm_action` | `"1"` → confirmar | → terminal (delete confirmado) → clearExpecting |
| `confirm_action` | `"2"` → modificar qty | → `select_quantity` |
| `confirm_action` | `"3"` → cancelar | → clearExpecting |
| `select_quantity` | número 1–N | → terminal (qty actualizada) → clearExpecting |

| Frase | Peso |

### Regex directos (ya en texto — no intent)

| Patrón | Ejemplo | Extrae |
|--------|---------|--------|
| `/(eliminar\|quitar\|sacar)\s+(\d+)/i` | `"eliminar 2"` | `{ action:'remove', index:2 }` |
| `/modificar\s+(\d+)/i` | `"modificar 1"` | `{ action:'modify', index:1 }` |

## Comportamiento

### Happy path — Eliminar ítem:
1. Usuario: `"modificar carrito"` → listar numerado + instrucciones + `expecting(select_action)`
2. Usuario: `"eliminar 2"` → menú confirmación: 1️⃣/2️⃣/3️⃣ + `expecting(confirm_action, remove, idx:2)`
3. Usuario: `"1"` → elimina ítem + muestra carrito actualizado + clearExpecting
4. Respuesta: `"✅ [nombre] eliminado. 🛒 Tu carrito: [items]. Total: $X"`

### Happy path — Modificar cantidad:
1. Usuario: `"modificar carrito"` → listar numerado + expecting
2. Usuario: `"modificar 1"` → menú confirmación + expecting(confirm_action, modify, idx:1)
3. Usuario: `"2"` (opción modificar qty) → pregunta cantidad + expecting(select_quantity)
4. Usuario: `"3"` → valida stock → actualiza → carrito actualizado + clearExpecting

### Edge cases:
- Número fuera de rango en cualquier paso → error + mensaje claro (sin cambio de estado)
- Carrito vacío → `"Tu carrito está vacío"` + hint búsqueda (sin setear expecting)
- TTL de 10 min vence → clearExpecting implícito (manejado por ExpectingService.getExpecting())
- `"3"` en confirm menu → cancela + clearExpecting (no crash)
