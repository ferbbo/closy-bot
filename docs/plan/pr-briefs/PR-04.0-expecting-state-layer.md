# Brief — PR-04.0 — Expecting State Layer + PlaybookMessages Unificados

> **Status**: `APPROVED`
> **Scope**: `MVP` (infraestructura)
> **Archivo**: `docs/plan/pr-briefs/PR-04.0-expecting-state-layer.md`
> **Issue**: #132
> **Parallel Mode**: `false`
> **Regla**: Max 2 páginas. Spec-locked. Sin scope extra.

## Objetivo

Crear capa unificada de estado `expecting` como **único mecanismo** de estado multi-paso para todos los flujos conversacionales (búsqueda, carrito, checkout). Migrar `CheckoutService.persistState()` para usar `ExpectingService`, eliminando `metadata.checkout` como mecanismo separado. Extender `PlaybookMessages` con 22 keys nuevas y agregar helpers de parsing/formato numérico. Sin migración de base de datos: `metadata (Json?)` ya existe.

## Scope fence

### ✅ Included

- Interface `ExpectingState` con `flow`, `type`, `data`, `expiresAt` (TTL variable: 10 min carts/search, 30 min checkout)
- `ExpectingService`: set/get/clear/isExpecting; fuente única de verdad para estado multi-paso
- Migración `CheckoutService`: `persistState()` y `getCheckoutState()` delegados a `ExpectingService`; eliminado `metadata.checkout` como clave separada
- `RouteDecisionService` consulta `expecting` activo antes de clasificar intent (pre-hook)
- `SearchCatalogFlow.handle()` guarda `metadata.lastSearchResults` + setea `expecting: select_product` post-búsqueda
- 22 nuevos `PlaybookMessages` keys + defaults en 4 presets (generic/ropa/belleza/minimarket)
- Helpers: `formatNumberedList()` (emojis 1️⃣…9️⃣) y `parseNumericSelection()` (texto → número)
- Registro de `ExpectingService` en `orchestrator.module.ts` + inyección en `CheckoutService`

### ❌ Excluded

- Implementación de flujos guiados (PR-04.1 add-to-cart, PR-04.2 modify/remove)
- Migración Prisma (`Conversation.metadata Json?` ya existe)
- UI editor de mensajes
- Handlebars / template engine (Bloque 7 PR-22)
- TTL configurable por merchant (V1: hardcoded)

### Persistencia

- **Sin migración**: `Conversation.metadata (Json?)` existe desde PR-05.
- **Patrón RW**: `existingMeta = (conversation.metadata as Record<string,unknown>) ?? {}; updatedMeta = { ...existingMeta, expecting: state }` — `expecting` es la única clave de estado multi-paso.
- **Migración checkout**: `metadata.checkout` deja de usarse. `CheckoutService` escribe/lee vía `ExpectingService`. Datos de sesión checkout viven en `data.cartId`, `data.checkoutName`, etc.
- **Mapeo `CheckoutStep` → `type`**: `ASK_NAME`→`input_name`, `ASK_ADDRESS`→`input_address`, `SELECT_PAYMENT`→`select_payment`, `CONFIRM`→`confirm_order`, `COMPLETED`→`clearExpecting()`
- **TTL**: checkout TTL = 30 min (usuario puede tardar en responder nombre/dirección/pago).

## Comportamiento

**Happy path (búsqueda → selección → agregar al carrito):**
1. Usuario: `"buscar camisetas azules"` → `SearchCatalogFlow` guarda `lastSearchResults` + `expecting: { flow:'search_selection', type:'select_product', data:{ products, page:1, hasMore:false } }`
2. Usuario: `"2"` → PR-04.1 muestra menú de opciones → `expecting: { flow:'search_selection', type:'product_options', data:{ selectedProduct:{ id, name, price } } }`
3. Usuario: `"1"` (agregar al carrito) → PR-04.1 agrega 1 unidad al carrito → `clearExpecting()` → responde `addToCartConfirm`

**Happy path (búsqueda → paginación):**
1. Búsqueda retorna >5 items → `expecting: { flow:'search_selection', type:'select_product', data:{ page:1, hasMore:true } }`; `{nextHint}` = `"\nPara ver más: *siguiente*"`
2. Usuario: `"siguiente"` → PR-04.1 carga pág 2 → actualiza `expecting: { ..., data:{ page:2, hasMore:false } }`

**Happy path (búsqueda → ver detalles → agregar):**
1. (desde `product_options`) Usuario: `"2"` → PR-04.1 muestra detalles del producto → `expecting: { flow:'search_selection', type:'view_details', data:{ selectedProduct } }`
2. Usuario: `"1"` → PR-04.1 agrega 1 unidad al carrito → `clearExpecting()` → responde `addToCartConfirm`

**Happy path (bare "buscar" → pedir keyword):**
1. Usuario: `"buscar"` (sin keyword) → PR-04.1 setea `expecting: { flow:'search_selection', type:'ask_search_query', expiresAt:+10min }` + responde `searchAskKeyword`
2. Usuario escribe keyword → PR-04.1 ejecuta búsqueda normal

**Happy path (búsqueda → cancelar):**
- (en estado `select_action`) Usuario: `"3"` → `clearExpecting()` → mensaje `searchCancelled`

**Happy path (cart_management — eliminar):**
1. Usuario: "listar carrito" o "modificar carrito" → PR-04.2 muestra lista numerada + `expecting: { flow:'cart_management', type:'select_action', data:{ cartItems:[...] } }`
2. Usuario: "eliminar 2" → PR-04.2 guarda selección + muestra menú → `expecting: { flow:'cart_management', type:'confirm_action', data:{ cartItems, selectedItemIndex:2, pendingAction:'remove' } }`
3. Usuario: "1" (confirmar eliminación) → PR-04.2 elimina item → muestra carrito actualizado + total → `clearExpecting()`

**Happy path (cart_management — modificar):**
1. (desde lista activa) Usuario: "modificar 1" → `expecting: { flow:'cart_management', type:'confirm_action', data:{ cartItems, selectedItemIndex:1, pendingAction:'modify' } }`
2. Usuario: "2" (modificar cantidad) → `expecting: { flow:'cart_management', type:'select_quantity', data:{ selectedProduct, maxStock, pendingAction:'modify' } }`
3. Usuario: "3" → PR-04.2 actualiza cantidad → muestra carrito actualizado + total → `clearExpecting()`

**Happy path (cart_management — cancelar):**
- Usuario: "3" en `confirm_action` → `clearExpecting()` → mensaje `cartActionCancelled` + hint `cartManagementHint`

**Happy path (checkout → 4 pasos vía ExpectingService):**
1. `CheckoutService.startCheckout()` → `setExpecting({ flow:'checkout', type:'input_name', data:{ cartId, startedAt }, expiresAt: +30min })`
2. Usuario da nombre → `setExpecting({..., type:'input_address', data:{ cartId, checkoutName:'Juan' } })`
3. Usuario da dirección → `setExpecting({..., type:'select_payment', data:{...} })`
4. Usuario selecciona pago → `setExpecting({..., type:'confirm_order', data:{...} })`
5. Usuario confirma → `CheckoutService.createOrder()` → `clearExpecting()`

**Edge cases:**
- TTL cart/search >10 min: `getExpecting()` devuelve null → mensaje `searchExpired`
- TTL checkout >30 min: `getExpecting()` devuelve null → `CheckoutFlow` trata como `NO_CHECKOUT_STATE` (mismo comportamiento que antes)
- `clearExpecting()` se llama al completar add-to-cart, al confirmar/cancelar `cart_management`, o al crear orden
- `parseNumericSelection("lo quiero", 5)` → null; solo dígitos enteros en rango `[1, max]` son válidos
- Conversation sin metadata previa: `getExpecting()` retorna null sin error
- Backward compat: conversaciones con `metadata.checkout` existente (en curso) deben seguir funcionando — `CheckoutService.getCheckoutState()` lee de `ExpectingService`; si no hay `expecting` activo, retorna null (checkout reinicia)

## Constraints

- Guardrails: datos en `lastSearchResults` provienen de `CatalogService`, nunca del LLM.
- PII: no almacenar teléfono/nombre de usuario en `lastSearchResults` ni en `ExpectingState`.
- TTL hardcodeado a 10 min (no configurable en V1).
- **Keywords de entrada (acotadas)**: 3 keyword-triggers únicos: `buscar [keyword]`, `modificar carrito`/`listar carrito`, `siguiente`. Todo lo demás son dígitos `[1-N]`. Patrón uniforme: keyword para iniciar flujo + número para seleccionar/confirmar. No agregar sinónimos ni variantes (aumenta complejidad sin valor).
- Clases con propiedades decoradas en NestJS: usar `!` (definite assignment assertion).
- Patrón Prisma JSON: `as unknown as Prisma.InputJsonValue` obligatorio en el `update()`.
